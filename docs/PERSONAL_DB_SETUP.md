# 내 DB 적용 / 기존 데이터 보존 (Palja)

> **개인정보 주의:** 이 저장소는 공개입니다. 개인 명식, 실제 출생일시, 상담 메모, 사진, 백업 JSON, 기존 앱 APK, 개인 서명키를 커밋하거나 공개 Actions 아티팩트에 넣지 마세요.

## 1. 기존 휴대폰에서 업데이트할 때 — DB를 덮어쓰지 않습니다

- 기존 앱이 `com.newwonwoo.saju`이고 새 APK의 **서명 인증서가 동일**하며 versionCode가 더 높으면 앱을 삭제하지 않고 업데이트할 수 있습니다.
- 앱 내부 저장 DB는 `getNoBackupFilesDir()/saju-vault.sqlite3`입니다. 패키지·서명이 유지되는 정상 업데이트에서는 내부 파일이 남습니다.
- **업데이트 전에** 앱의 **설정과 백업 → 백업 내보내기**로 JSON 백업을 기기 외부나 드라이브에 보관합니다.
- 앱 삭제, 설정의 데이터 삭제, 디버그 APK 덮어쓰기, 기존 키와 다른 서명은 금지합니다.
- 업데이트 이후 명식 수·메모·그룹·즐겨찾기·휴지통을 확인하고, 앱을 종료/재실행해서 재검증합니다.
- DB를 초기 시드 파일로 **강제 덮어쓰지 않습니다**.

## 2. 새 휴대폰에 최초 설치 / 복원

1. 원래 앱에서 **설정과 백업 → 백업 내보내기** 버튼으로 `.json` 파일 생성.
2. 새 앱 설치 후 **설정과 백업 → 자료 가져오기**에서 해당 JSON 선택.
3. 추가/기존/충돌 건수를 확인하고 가져오기 확정.
4. 수, 이름, 그룹, 메모, 수정 기록, 사진·그림 등을 비교합니다.

현행 파일 종류는 두 가지입니다.

| 입력 파일 | `format` 필드 | 앱에서 가능한 작업 |
|---|---|---|
| 앱 백업 | `saju-vault-backup` | '자료 가져오기'로 **병합/복원** |
| 최초 수집 명식 패키지 | `saju-vault-screenshot-import` | '자료 가져오기' 또는 APK 최초 1회 사전 주입 |
| SQLite 원본 (`.db`, `.sqlite3`) | 해당 없음 | **직접 가져오기 미지원**. 별도 오프라인 변환 및 데이터 검증 필요 |

**가져오기는 안전한 병합**이며 이미 수정하거나 삭제한 로컬 기록을 덮어쓰지 않습니다. 완전 교체를 원하는 경우에도 먼저 별도 JSON 백업이 필요하며, 기기 DB를 임의 삭제하는 방법은 지원하지 않습니다.

## 3. 첫 설치 시 개인 명식이 들어 있는 *전용* APK를 만들 때

앱에는 이미 **최초 1회 시드 주입 기능**이 있습니다.

- `vite.config.js`는 모바일 빌드 중 **`SAJU_SEED_FILE`** 환경변수로 지정한 **로컬 JSON 파일**을 읽습니다.
- 파일은 `saju-vault-screenshot-import` 형식이어야 하고 8 MiB 이하여야 합니다.
- 빌드 결과에 `private/initial-vault.json`이 포함됩니다. 단, 이 파일을 공개 Git에 만들지 않습니다.
- `src/vault/persistence.js`의 `initializeVault()`는 **저장 DB revision 0(아직 비어 있을 때)에만** 그 패키지를 가져옵니다. 저장 기록이 있으면 시드를 다시 적용하지 않습니다.
- `SAJU_SEED_FILE=/개인/로컬/명식.json npm run android:sync`로 로컬 생성 후, 기존 개인 서명키를 통해 별도로 APK를 서명해야 업데이트 설치가 가능합니다.
- **주의:** APK 안에 포함된 JSON은 APK 파일을 입수한 사람이 추출할 수 있는 *평문 데이터*입니다. 절대 공개 배포하지 마세요. 사생활 보호에는 **시드 없는 APK + 기기 내부에서 JSON 백업 가져오기**가 더 안전합니다.
- 기존 앱에 넣어 둔 163개는 과거 개인 APK의 사전 주입 자료이며, 공개 GitHub 소스와 공개 빌드에는 없습니다.

## 4. 현재 X 버튼 수정판

- X가 스크롤로 연결된 문제를 1.1.3 코드에서 바로잡았습니다.
- `SajuVault.exitApp()`은 활동 화면을 닫을 뿐 SQLite를 삭제하지 않습니다.
- 새 버전 패키지 ID는 `com.newwonwoo.saju`, versionCode 13입니다.
- 이 공개 저장소의 테스트용 APK는 개인키/명식이 없습니다. **기존 개인 APK와 서명이 다르면 업데이트 설치할 수 없습니다.**
- 기존 1.1.2 앱을 삭제하지 마세요. 동일 인증서로 서명한 개인 업데이트 APK가 준비될 때까지 현재 앱은 보존합니다.

## 5. 개인 자료를 이 대화에서 처리할 경우

- **앱 JSON 백업**을 대화에 첨부하면 파일 형식을 검증하고, 1.1.3 앱에 안전하게 적용할 절차를 마련할 수 있습니다.
- **SQLite만 있으면** 테이블 스키마를 확인하고 JSON 변환을 검토합니다.
- 비밀번호/서명 개인키는 공개 메시지, GitHub 이슈, 공개 저장소에 올리지 마세요.
- 원본 8자어때 APK만으로는 기기에 별도로 저장된 실제 친구 DB를 추출할 수 없습니다. 해당 기록은 별도 백업/내보내기가 필요합니다.

## 6. 소유자가 확인한 원본 기호를 기존 저장자료에 적용

- 개인 빌드에서만 `SAJU_IMPORT_MAPPINGS_FILE`로 별도 로컬 JSON을 지정할 수 있습니다. 공개 빌드에는 포함하지 않습니다.
- 형식은 `format: "saju-vault-confirmed-mappings"`, `version: 1`, 원본 `namespace`, 기존 가져오기 설정 형태의 `mappings`입니다. 이름에서 성별을 추측하지 않고 소유자가 확인한 기호의 의미만 담습니다.
- 시작 시 새 시드와 기존 저장자료 모두에 적용합니다. 지정 namespace의 미확인 값만 채우며 다른 자료, 확정값, 삭제 항목, 메모, 원본 payload는 유지합니다. 변경 전 출생정보는 수정 이력에 보존합니다.
- 이미 적용한 설정은 다시 저장하지 않습니다. 새로고침마다 revision이나 수정 이력이 늘어나지 않습니다.
- 초기 시드 파일은 원본 그대로 둡니다. 사용자별 namespace와 기호 확인 파일은 공개 저장소·공개 CI에 커밋하지 않습니다.
