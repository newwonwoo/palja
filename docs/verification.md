## 실제 화면 흐름

빌드한 모바일 정적 자산을 로컬 HTTP에서 열고 Playwright 1.51.1 / Chromium 134로 확인했습니다. 브라우저 전용 플러그인이 없어 임시 Playwright 스크립트를 사용했습니다. 기본 제공 Playwright 브라우저의 다운로드 URL에서 ZIP을 받지 못해, 공식 Microsoft 다운로드 경로를 이용하는 고정 버전을 별도 검증 폴더에 설치했습니다. 검증 도구는 앱 의존성에 추가하지 않았습니다.

다음 8개 시나리오가 통과했습니다.

1. 원본 가져오기 자료의 전체 항목·출처 행·즐겨찾기 수를 대조하고, 역법·성별 미확인 값을 유지했습니다.
2. 이름·메모·즐겨찾기를 수정한 뒤 재실행해 저장 상태를 확인했습니다. 미상 시각은 `null`로, 원본 출처는 그대로 유지했습니다.
3. 삭제 후 같은 자료를 다시 가져와 추가 항목 0개, 수정 내용과 삭제 상태 보존을 확인했습니다.
4. 잘못된 파일을 거부하며 저장 버전이 바뀌지 않는지 확인했습니다.
5. UI에서 내보낸 백업을 새 브라우저 저장소에 가져와 원문·수정·휴지통을 복원하고, 휴지통의 명식을 되살렸습니다.
6. 화면을 연 뒤 네트워크를 끄고 새 명식 저장과 미상 시각의 부분 명식 계산을 확인했습니다.
7. 개인정보 없는 예시 명식으로 360·390·800px 화면을 시각 점검했고 가로 넘침이 없었습니다.
8. 궁합의 상대방 입력이 빈 값으로 시작하고, 시·분을 비웠을 때 자정으로 계산하지 않고 입력을 요청하는지 확인했습니다.

8개 시나리오 동안 페이지 오류 0건, 콘솔 오류 0건, 외부 요청 0건입니다. 앱 내부 자산을 제공하는 로컬 요청은 외부 요청에 포함하지 않았습니다. 개인 자료와 브라우저 스크린샷·임시 백업은 공개 소스에 포함하지 않았습니다.

별도로 새 저장소에서 패키지에 담긴 초기 자료가 한 번만 로딩되고, 명식 추가 후 재실행해도 다시 초기화하지 않는지 확인했습니다. 이 시나리오도 통과했습니다. 일반 소스 빌드는 비어 있는 보관함으로 시작합니다.

## 설치 파일

개인용 개발 APK 1.0.0을 조립하고 APK Signature Scheme v2 서명을 검증했습니다. 컴파일된 manifest에 인터넷·외부 저장소 권한이 없으며 자동 백업과 원격 페이지 이동을 차단했습니다. APK에 담긴 초기 자료는 제공한 원본 파일과 바이트 단위로 일치합니다. 개인 APK와 서명키는 공개 저장소에 올리지 않습니다.

## 검증 과정에서 수정한 문제

- 기존 대운 그래프는 빈 목록에서 좌표를 읽어 상세 화면이 멈췄습니다. 빈 목록 안내와 단일 점 좌표 처리를 추가했습니다.
- 궁합의 빈 시각을 `0`으로 변환하던 경로에 빈 값·범위·정수 검사를 추가했습니다.
- 저장 중 새로 입력한 메모·폼 값이 사라지지 않도록 해당 입력을 잠급니다.
- 저장 데이터는 한도 안인데 들여쓴 백업은 한도를 넘던 문제를 컴팩트 직렬화와 백업 크기의 사전 검사로 해결했습니다.
- Android 기본 DB 손상 처리로 파일이 지워지지 않도록 원본 보존 처리를 적용했습니다.
- Capacitor의 개발 로그에 플러그인 인수가 남지 않도록 로그를 끄고 WebView 디버깅을 비활성화했습니다.

## 남은 확인 범위

APK 조립·서명·권한 검사와 JVM 테스트는 실제 휴대폰의 실행을 대신하지 않습니다. Android 시스템 파일 선택기의 저장·취소·복원, 시스템 뒤로가기, 앱 종료 후 재실행, 비행기 모드에서의 새 실행은 대상 휴대폰에서 확인해야 합니다. 브라우저 정적 페이지의 네트워크 차단 후 재로드를 검증한 것은 아닙니다. Android는 APK 내부 자산을 사용합니다.

계산 테스트는 기존 결과의 회귀 확인입니다. 절입 시각, 역사적 시각 보정, 일부 연말 대운, 초기 음력 자료 범위 등의 기존 한계는 [README](../README.md)에 있습니다. 8자어때 현행 Android 앱의 결과와 대조한 검증은 아닙니다.
