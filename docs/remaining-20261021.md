# 2026-10-21 나머지 기능 구현 기록

이 문서는 독립 구현의 계약과 검증 범위다. 원본 앱 결과와 대조하지 않았다. 전체 완료 상태는 [체크리스트](IMPLEMENTATION_CHECKLIST.md)에만 기록한다.

## 자시와 시진 경계

기존 정책 버전 1에 선택 필드 `hourBoundaryOffset: 0 | 30`을 추가했다. 누락은 0이다. 보정한 현지 시각에서 12개 시진의 경계를 0/30분 늦춘다. 날짜는 자정에 바뀌며 `zi23` 선택일 때만 23:00/23:30부터 다음 날 일주를 쓴다. `zi-split`은 그 구간에 일주를 유지하고 시주에는 다음 날 일간을 사용한다. 00:30을 별도 일주 경계로 가정하지 않는다. 출생지 경도·DST·균시차 보정은 먼저 수행한다. 이는 ‘자오해사’라는 미정 명칭의 원본 동작을 복원한 주장이 아니다.

새 옵션은 기존 출생정보 정책 검증, 명식 편집, 계산, 선택운 계산, 전체 백업에서 같은 필드를 사용한다. 기존 명식의 기본 엔진과 저장값을 자동 변경하지 않는다.

## 외잡격 10종 계약

[삼명통회 권6](https://zh.wikisource.org/wiki/三命通會/卷六)의 구조 조건을 사용한다. 기존 곡직·염상·종혁·윤하·가색 다섯 후보의 배제 조건을 유지했다. 추가 구조는 다음과 같다.

| 이름 | 표시 조건 | 보류하는 해석 |
|---|---|---|
| 일귀 구조 | 丁酉·丁亥·癸巳·癸卯 일주 | 주야 구분, 형충파해, 다른 격 우선에 따른 격 확정 |
| 일덕 구조 | 甲寅·丙辰·戊辰·庚辰·壬戌 일주 | 재관·중첩·왕쇠·운행에 따른 성패 |
| 괴강 중첩 구조 | 庚辰·壬辰·戊戌·庚戌 일주이며 다른 한 기둥 이상도 이 네 조합 | 보존한 기존 신살의 6조합 변형과 구분. 길흉 확정 없음 |
| 녹원호환 구조 | 일시쌍 戊申/乙卯, 丁酉/壬寅, 丙子/癸巳, 庚子/丁亥 | 재관·형충·운행의 성패 |
| 자오쌍포 구조 | 子·午 각 2개, 또는 년→월→일→시에서 子午子/午子午 포위 | 다른 해석의 불연속 포위 변형·길흉 확정 없음. 충도 함께 표시 |

내격은 사용자가 고른 본기/투간 규칙이 우선이다. 응용격과 외잡격을 함께 표시하며 자동으로 내격을 대체하지 않는다. 제외 조건이 있는 기존 다섯 후보는 이를 먼저 검사한다. 일덕/괴강처럼 중복 가능한 구조는 모두 표시한다. 별도 강약 문턱으로 종격을 억지 생성하지 않는다. 10종의 양성·음성, 불완전 기둥, 중복/우선순위 테스트가 있다. 화면에서 버전 목록과 순서를 열람할 수 있다.

## 지원 신살 38종

십이신살 12종, 보존한 천을·양인·백호·괴강·원진 5종, 천간 기준 문창·금여·국인·태극·홍염·유하·건록 7종, 천덕·월덕·천의·고신·과숙·홍란·천희·귀문·천덕합·월덕합·공망·천라 지지쌍·지망 지지쌍·십악대패 일주 14종이다. 전체 목록은 `SHINSAL_CATALOG.names`가 관리하며 화면에도 표시한다.

근거는 [삼명통회 권3](https://zh.wikisource.org/wiki/三命通會/卷三)과 보존한 공개 조견표다. 홍염은 戊子·壬巳 변형을 사용한다. 천덕의 사정월 지지 변환과 그 육합은 선택한 지지 대응 변형이다. 공망은 해당 일/년주의 10간 순중 빠지는 지지 둘이다. 십악대패는 건록이 순중 공망인 10일주만 표시한다. 공개 전사본의 己丑/乙丑 오기는 己丑의 건록 午가 甲申旬 공망 午未라는 조건으로 검증한다. 천라·지망은 두 지지의 공존만 분류하며 성별·납음별 사건 해석을 하지 않는다.

천간 기준 6개 추가표는 10간×12지의 양성/음성 전수 검사, 건록은 10간, 천덕/고신/과숙은 12지, 공망은 60갑자를 검증한다. 신살 제외 선택 시 기존 고정 신살도 제거하도록 수정했다. 월지 신살 설명에서 月을 해당 주라고 표시하던 문구도 월지로 수정했다.

## 업데이트와 데이터 보존

소스 버전은 1.1.5/versionCode 15다. Android CI에서 debug와 **unsigned release**를 만든다. unsigned 파일은 설치할 수 없으며 개인키로 서명하기 전 단계다. 개인 데이터와 서명키는 CI에 제공하지 않는다.

`VaultUpgradePreservationTest`는 현재 저장 도우미를 거치지 않고 과거 schema v1 DB를 생성해 기존 JSON과 revision 읽기, 편집 후 재열기 보존을 검사한다. schema v2를 만났을 때 원래 행을 삭제/초기화하지 않는지도 검사한다. 실제 앱 업데이트 설치 테스트는 아니다.

`verify-upgrade-backups.mjs`는 설치 전후 전체 백업을 읽기 전용으로 비교한다. 원래 ID를 가진 모든 기록과 중첩 내용이 보존되어야 하며 최근 열람과 루트 revision만 제외한다. 즐겨찾기·그룹·메모·사진·그림·이력·휴지통의 변경을 탐지하는 합성 테스트가 있다. 결과에 개인 값은 출력하지 않는다. 두 백업에 이미 공통으로 누락된 데이터는 알아낼 수 없으므로 설치 전 전체 백업을 별도로 보관해야 한다.
