# 개인용 오프라인 통합판 1.1.0

## 계획과 실행 범위

중단 전 원격에 남은 것은 도구 준비 커밋 e8fe35c뿐이었다. 기존 기능 커밋 c6002c0에서 이어서 다음 묶음을 하나의 배포 대상으로 구현했다. main은 변경하지 않는다.

| 묶음 | 입력 → 동작 → 결과 | 보존 및 제한 |
|---|---|---|
| 독립 역법 | 출생정보 수정 → 계산 엔진 명시적 선택 → 1900~2050 음양력·절입·시각 보정·10대운 | 기존 기록 자동 전환 없음. 대운 시작일과 균시차는 명시된 근사 방식 |
| 비중·선택운 | 궁성/지장간/대운·년월일시 비중 편집 → 저장 → 오행·음양 변경 | 용신·신강약·격국은 기존 원국 판정. 합화 자동 판정은 미연결 |
| 날짜별 상담 | 여러 메모·날짜/분류/검색·사진·그림·운 선택·이력 → 저장/재열기/삭제/복원 | 본래 한 줄 메모와 별도. 최근 10개 이력. 전체 저장/백업 8MiB |
| 선택 자료 | 단일/그룹 명식 선택 → 메모 포함 선택 → JSON 내보내기/가져오기 | 기본 메모 제외. 비선택 인물이 들어 있는 원본 스크린샷 소스 묶음 제외 |
| 만세력 도구 | 독립 음력·절기 달력 → 날짜 선택 → 새 입력 | 1900~2050년. 달력 절기 표시는 고정 UTC+09:00. 4주 역검색은 기존 역법 |
| 직접 입력 대운 | 네 기둥과 대운수/방향/시작 연도 선택 → 10개 대운 | 생일을 만들지 않음. 시작 연도 미상이면 나이표만 표시하고 특정 해에 배정하지 않음 |

원본 상세 캡처의 세운·대운·시·일·월·년 6열, 운 목록, 상단 풀이 탭과 하단 5개 메뉴 구조는 유지한다. 새 입력·사진·비중 편집 UI는 동일한 시각 체계로 독립 구현한 것으로 원본 픽셀 동일성을 주장하지 않는다.

## 구현과 원본 동등성의 구분

79개 작업 단위는 확정된 원본 기능 총수가 아니다. 기능 구현 상태와 원본 결과/조작 대조를 별도 관리한다. `check-full-feature-scope.mjs --require-complete`는 미검증 항목이 있는 동안 실패한다. 안내만 뜨는 버튼은 구현 완료로 세지 않는다.

미완료 핵심: 원본 전용 합화 비중, 모든 격국/병약용신/신살, 분야별 운세·궁합 점수/튜닝, 전체 표시·디자인 옵션, 공개 인물 데이터, 유사 명식, 원본 운세 트리와 여러 프리셋. 로그인·광고·결제/원본 서버의 접근 제어를 우회하지 않는다.

## 계산 근거

- 태양 황경 탐색: Astronomy Engine **2.1.19**, `SearchSunLongitude`. 라이브러리를 앱에 포함하고 네트워크 없이 계산한다. [공식 API](https://github.com/cosinekitty/astronomy/blob/master/source/js/README.md#SearchSunLongitude)
- 한국 음력: **korean-lunar-calendar 0.4.0**, 입력 검증/윤달/변환. [저자 저장소](https://github.com/usingsky/korean_lunar_calendar_js)
- 역사적 한국 시각: **IANA tzdb 2025b Asia/Seoul**, 시간 전환표를 정규화하여 포함. 반복 시각은 먼저/나중을 선택하고 공백 시각은 거부한다. [데이터](https://data.iana.org/time-zones/tzdb-2025b/asia)
- 균시차: **NOAA 분수년 조화식 근사**. 경도 보정 및 DST와 중복 적용하지 않는다. [원문 공식](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)
- 독립 비교값: **NAOJ 2024년 24절기** 발표의 중앙표준시(UTC+09:00)를 기준으로 각 항목 2분 이내 회귀 테스트. [일본 국립천문대](https://eco.mtk.nao.ac.jp/koyomi/yoko/2024/rekiyou242.html)

이는 8자어때 Dart AOT의 원래 산식 복원이 아니다. NAOJ 대조는 2024년 24개 절기에 한정된다. 초 단위 정확성이나 모든 연도의 원본/KASI 값 동일성을 보증하지 않는다. 시간대 데이터 역시 버전이 고정된 공개 데이터이며 역사 자료 자체의 불확실성은 남는다.

## 데이터와 저장 보호

`birth.calculation_policy`, 직접 간지용 `birth.manual_daeun`, 선택적 `workspace.integrated`를 추가했다. 기존 v1 저장 상태를 읽고, 바뀐 입력은 수정 이력과 함께 보존한다. 필드를 모르는 구버전 앱에 새로운 백업을 가져오는 것은 지원하지 않는다.

여러 메모·옛 메모의 동시 저장은 하나의 저장소 revision으로 정규화한다. 사진 처리 중 화면 이동/저장을 막고, 내비게이션·브라우저 history 뒤로가기에는 저장 확인을 둔다. 오래된 백업이 로컬 메모·삭제 상태·비중/선택운을 덮어쓰지 않는다.

사진은 JPG/PNG/WebP, 한 파일 입력 12MB 이하, 최대 1280px로 정규화하여 EXIF를 포함하지 않는 JPEG로 저장한다. 메모당 4장, 그림은 PNG. 사진/그림/이력도 기존 8MiB 저장 한도에 포함되어 한도 초과 시 기존 자료를 보존하며 저장을 거부한다.

## 검증 명령

```sh
npm ci
npm test
node scripts/verify-integrated-boundaries.mjs
node scripts/check-full-feature-scope.mjs
npm run build
npm run build:mobile

# 별도 테스트 도구 설치 위치 지정. 합성 데이터만 사용.
node scripts/generate-integration-fixture.mjs /tmp/saju-ui-check
QA_DIR=/tmp/saju-ui-check PLAYWRIGHT_MODULE=/path/to/playwright node tests/browser/integrated.cjs
```

로컬 확인: 단위 테스트 184개, Chromium UI 점검 39개, 320/360/390/800px 검증. 흐름: 기존 명식→새 엔진 선택→비중 편집→날짜/시각 선택→사진/그림 메모→이력 복원→백업/빈 저장소 복원, 오프라인 조작, 뒤로가기 보호, 음력/절기 달력, 직접 대운수 수정/재열기.

Browser 플러그인이 없어 Playwright 1.51.1/Chromium을 사용했다. 초기 화면·오류 오버레이·콘솔·실제 조작·저장값을 확인한다. 오프라인 검증은 최초 로드 이후 네트워크 차단이며 Android 실기기의 오프라인 새 시작과 다르다.

## 설치물 검증 경계

GitHub에서는 개인 자료 없는 APK를 빌드한다. 개인 APK는 로컬에서 이전 초기 자료와 기존 키로 서명한다. 원본 앱 APK·개인 자료·폰트·서명키는 공개 저장소에 넣지 않는다. 업데이트는 삭제하지 않고 수행하며 설치 전에 JSON 백업을 먼저 만든다.

Android 실기기 설치, 시스템 파일 선택기, 실제 업데이트 뒤 DB 보존은 아직 검증하지 않았다. 서명/패키지/자료 일치 검증만으로 실기기 성공을 보증하지 않는다. 최종 서명·SHA는 별도 제공 검증 기록을 따른다.
