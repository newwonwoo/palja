# 원본 APK 나이 표기 분석과 구현

2026-10-20에 전체 해시가 검증된 8자어때 18.2.8의 ARM64 `libapp.so`를 분석했다. 원본 바이너리·분석기 출력은 저장소 밖에 보관한다. 이 문서는 독립 구현에 필요한 동작 관찰과 주소만 기록한다.

## 원본 정적 근거

Blutter의 Dart 3.12.0 분석기가 함수별 ARM64 코드와 객체 풀 덤프를 생성했다. 기존 모듈 경로 나열 단계보다 확인 범위가 넓어졌지만, 실제 앱을 실행한 결과와 구분한다.

| 확인 대상 | 원본 근거 | 관찰 |
|---|---|---|
| 나이 선택지 | `core/domains/age/age_notation.dart`, 객체 `0xc44801`, `0xc44821` | enum 값은 `ENG_AGE`, `KOR_AGE` 두 개. 연 나이 선택지는 확인되지 않음 |
| 설정 화면 | `features/setting/presentation/manse_settings/age_notation_options.dart`, `build` `0xc994e4` | 한국 나이와 만 나이 두 선택지, 표시 나이 기준 섹션 |
| 기본값 | `features/setting/application/general_settings_providers.dart`, `0x7a22e8–0x7a22f8` | 저장된 설정이 null이면 `KOR_AGE` 반환 |
| 저장 | `features/setting/data/setting_repository.dart`, `getAgeNotation` `0x7a2310` | `age_notation` 정수 인덱스를 저장·조회 |
| 한국 나이 | `core/domains/age/age_calculator.dart`, `_getKorAge` `0x7a6dbc` 및 `getAgeByNotation` `0x7a69a8` | 과거 출생의 정상 입력에서 기준 연도 − 출생 연도 + 1. 미래 출생 관련 별도 분기는 추가 대조 필요 |
| 만 나이 | 같은 파일, `_getEngAge` `0x7a6c20` | 연도 차이에 월·일 생일 경과 여부를 반영 |
| 윤일 경계 | `_getEngAge` `0x7a6cf0–0x7a6d7c` | 양쪽 월·일을 비윤년인 1000년 DateTime으로 정규화한 뒤 비교. 2월 29일은 3월 1일로 정규화됨 |

윤일 경계는 일반적인 월·일 직접 비교와 다르다. 예를 들어 2000-03-01 출생, 2024-02-29 기준 입력은 이 원본 함수의 정규화 규칙상 24가 된다. 실제 원본 UI에서 동일 입력을 실행한 검증은 아직 하지 않았으며 이 경계는 원본 함수 분석에 따른 재현이다.

## Palja에 연결한 범위

- 설정에 한국 나이·만 나이 두 선택지를 추가하고 원본과 같이 한국 나이를 기본으로 읽는다.
- 선택값을 `workspace.preferences.ageNotation`에 저장하고 백업·복원한다. 필드가 없는 기존 자료도 유효하며, 읽는 것만으로 저장된 문서를 수정하지 않는다.
- 보관함의 나이 배지, 나이 검색, 나이순 정렬에 같은 기준을 적용한다.
- 기존 출생정보, 캡처 나이, 명식 ID, 그룹, 메모는 변경하지 않는다.
- 확인된 양력 또는 기존의 기본 양력 정책이 적용되는 유효한 과거 날짜를 계산한다. 확인되지 않은 음력·미래 출생·간지 직접 입력에 임의의 생일을 만들지 않는다.
- 세운·대운 나이는 기존의 별도 계산·표시를 유지한다. 원본 연도 전용 함수와 미래 출생 분기, 음력 변환 및 상세 화면 전체 동기화는 남아 있다.

## 검증과 한계

- 새 Node 테스트 6개: 두 선택지·기본값, 생일 전후·연도 경계, 원본 윤일 정규화, 잘못된 날짜·미래 입력 차단, 나이 검색·정렬, 구버전 백업 호환·복원·로컬 설정 우선·부정 값 거부.
- JavaScript 전체 테스트 223개 통과.
- 웹·모바일 프로덕션 빌드 통과.
- Playwright/기존 Chromium: 나이 설정 흐름 16개, 기존 화면 설정 흐름 18개 통과. Browser plugin not available로 기존 Playwright를 사용했다. 320·390·800px 가로 넘침 없음, 새 흐름의 런타임 오류 없음. 캡처와 합성 데이터는 저장소 밖에 보관한다.
- 원본 앱의 실제 실행 결과·실기기 업데이트는 이 검증에 포함되지 않는다. 이 항목은 아직 원본 대조 완료로 체크하지 않는다.
