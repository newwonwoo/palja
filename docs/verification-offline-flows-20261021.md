# 오프라인 입력·분류·기록·백업 검증

## 확인한 변경

- 메모에서 ‘기록 당시 운 선택’을 적용하면 화면만 바뀌던 문제를 수정했다. 저장 성공 후 운세 화면으로 이동하며, 선택 날짜·시각이 재열기와 백업에도 유지된다. 저장 실패 시 적용한 것처럼 화면을 전환하지 않는다.
- 다른 탭이 먼저 저장해 revision 충돌이 생길 때, 최신 명식을 읽는 효과가 작성 중인 텍스트까지 덮어쓰던 문제를 수정했다. 저장된 기준값과 같았던 깨끗한 입력만 동기화하고, 편집 중인 초안은 남긴다. 오래된 탭은 최신 DB 행을 덮어쓰지 못한다.
- `npm run progress`와 체크리스트가 코드 구현률·전체 검증률·개별 검증 항목 통과율을 각각 보고한다. 79개 전 항목에 7개 검증 항목을 등록했다. 근거 없는 항목은 대기로 남겼다.

## 실제 실행 근거

코드 `8521d9679a8101879b6c8e701a1397013e3bd613`의 [브라우저 CI](https://github.com/newwonwoo/palja/actions/runs/39522863427)에서 신규 **67개 검사·23개 기능 ID**, 기존 확장 33·통합 39·운세/일괄관리 13개 검사, 독립 계산 표 및 종료 검사까지 통과했다. 자바스크립트 281개와 생산 빌드도 통과했다. 최종 변경의 추가 검사 및 Android 상태는 [PR #6](https://github.com/newwonwoo/palja/pull/6)의 최종 CI 결과를 따른다.

[합성 스크린샷·결과 JSON](https://github.com/newwonwoo/palja/actions/runs/39522863427/artifacts/12311986921)에 `remaining-results.json`, `remaining-journal-390.png`, `remaining-conflict-390.png`, `remaining-library-390.png`가 포함된다. 새 검사의 기록된 조작은 전부 오프라인 상태였다. 콘솔·런타임 오류는 0이며 메모 화면은 320/390/800px에서 외부 가로 넘침이 없었다.

현재 Browser `js` 도구가 제공되지 않아 기존 GitHub CI의 Playwright Chromium을 사용했다. URL은 CI 내부 `http://127.0.0.1:8765/`이며 합성 입력만 사용했다. 자산을 먼저 로드한 뒤 네트워크를 끄고 조작했다. 브라우저 새로고침 때는 자산을 다시 로드하고 오프라인으로 전환했다. 웹 브라우저의 오프라인 최초 실행을 검증한 것은 아니다. Android는 번들 자산과 SQLite를 사용하는 별도 환경이다.

## 23개 기능과 7개 검증 항목의 대응

공통으로 입력·조작은 실제 UI, 결과는 UI와 IndexedDB 상태/생성 파일을 교차 확인했다. 재열기·전체/선택 백업과 새 컨텍스트 가져오기로 보존 여부를 검사했다. 오프라인은 자산 로드 후의 조작을 의미한다. 회귀는 전체 JS·기존 브라우저·고정 계산/네이티브 파일 SHA 검사를 사용했다.

신살·격국 같은 전통 해석이 아닌 데이터/인터페이스 기능은 ‘공개 문헌 또는 독립 엔진(해당 시)’ 항목이 적용 제외다. 그 대신 위 데이터 보존·입력 규약·정렬/파일 형식·동시 쓰기의 독립적인 불변조건을 검증했다. 이 적용 제외를 계산 엔진·전통 해석 항목의 근거로 전파하지 않는다. 원본 앱의 결과를 직접 비교하지 않았다.

## 검증 범위의 한계

이 검증은 명시한 UI/저장 계약의 브라우저 및 JVM 회귀다. 실제 개인 서명·기기 업데이트·모든 Android 제조사에서의 공유 대상 UI·사용자의 기존 개인 DB 확인을 대신하지 않는다. 해당 확인은 data.upgrade에 남긴다. 새로고침 전에 자산이 캐시되지 않은 웹 브라우저의 완전한 오프라인 로드는 대상이 아니다.

현재 공정률: 코드 구현 78/79 (98.7%), 전체 검증 완료 33/79 (41.8%), 개별 검증 항목 321/553 (58.0%). 직전 전체 검증 10/79에서 23개 증가했다. 남은 전체 검증 46개 중 data.upgrade는 원래 개인키와 실제 설치 기기가 필요하다.
