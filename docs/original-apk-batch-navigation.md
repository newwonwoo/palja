생일자 표시는 현재 날짜의 월/일과 **출생 시 양력 월/일**을 비교한다. 매년 달라지는 음력 생일 재계산을 임의로 추가하지 않았다. 2월 29일을 다른 날짜로 치환하지 않는다. 역법 미확인·직접 입력 간지·잘못된 날짜·삭제된 명식은 제외한다. 기존 Palja의 출생자료에는 원본의 `isShowBirthday` 대응 값이 없으므로 `showBirthday`가 없는 기존 명식은 표시 허용으로 읽되, 날짜 확인 조건을 통과해야 표시한다. 원본의 필드 초기 기본값과 같다고 판정하지 않는다. 개별 숨김은 메모/관리 화면에서 저장하며 출생 이력을 만들지 않는다.

원본 운 컨텍스트는 날짜를 다시 생성하는 분기도 갖는다(`updateWoonseContext` `0x9c2b88`, 날짜 생성 `0x9c2cbc`). Palja는 기존 시·분 조회를 유지한다. 따라서 유형 전이의 정적 근거를 전체 시각 처리·분석 결과 일치로 확대하지 않는다. 월/년 이동은 월말을 해당 월의 마지막 유효일로 줄이는 독립 UI 규칙이며 원본의 절운/세운 시작 순간 탐색으로 주장하지 않는다.

## 대운 수정의 의미

- 명식표가 각 시작 순간에서 고정 길이만 더해 찾던 방식 대신, 트리와 같은 다음 시작/명시적 끝 경계를 사용한다. 시작 전과 범위 뒤에는 빈 대운으로 남긴다.
- 독립 계산의 10대운에 끝 순간을 함께 반환해 마지막 대운도 그 끝까지 판정한다. 시작일 계산식 자체는 기존의 `365.2425일/년` 근사를 유지한다.
- 대운 타일을 누르면 시작 연도만 바꾸지 않고 교운 순간 이후 첫 입력 가능한 현지 분으로 이동한다. 초가 포함된 역사적 표준시 차이도 검사한다. 연도 정보만 있는 기존/수동 대운은 연도 기준임을 유지한다.
- 연도·월 타일과 기록 당시 운 불러오기도 저장 후 적용한다. 조회 유형·시간을 다시 열었을 때 잃지 않는다. 저장 중 타일의 중복 조작을 차단한다.
- 기존 `App.jsx`의 계산 결과와 금본 회귀값은 유지한다. 연말/연초 인접 절기를 놓치는 기존 대운 엔진의 누락은 이번 변경으로 해결되었다고 주장하지 않는다.
